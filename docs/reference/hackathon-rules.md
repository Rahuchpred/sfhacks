## Tracks

### SFSU track: Build For SFSU (our main track)

Build an original AI-powered project that addresses a real problem or opportunity at SF State.

Requirements:

1. Addresses a clear problem or opportunity at SFSU.
2. Clearly identifies who at SFSU benefits (students, faculty, staff, a campus office, the wider community).
3. AI is an important part and performs a meaningful function, not a basic chatbot or add-on.
4. A working project to demo: prototype, proof of concept or deployed. Slides alone are not enough.
5. Explain how it could realistically be used or developed further at SFSU.
6. Consider responsible AI: identify privacy, security, accessibility, data, bias or other risks and explain how they are addressed.
7. At least one current SFSU student on the team.

Prizes (Amazon gift cards): 1st $750, 2nd $500, 3rd $250. Winners may be considered for continued development or a pilot with SFSU.

### GDG track: Build with AI for Social Good

Use Gemini to address a social or community problem.

Requirements:

1. Gemini is an important part of the project, not just a basic chatbot.
2. Built around a clear social or community problem.
3. Uses at least one Google developer tool or Google Cloud service besides Gemini (Antigravity, Gemini CLI, Google AI Studio, Vertex AI, Firebase, Cloud Run, Firestore, Cloud Storage, etc.).
4. **Must use the Google Cloud credits provided for the hackathon.**
5. A working project to demo.

Prize: one winning team, $500+ of Google equipment and products.

### MLH: Best Open-Source AI Project

Open-source or open-weight AI must be an important part.

- Public GitHub repo with an open-source license (MIT, Apache-2.0, GPL-3.0, etc.)
- Name the model and link its license or terms in the README
- An agent skill must follow the Agent Skills open standard
- A model-harness entry needs an original implementation or meaningful changes to an existing one

Prize: DEV badge for each member, possibly MLH+DEV swag.

### MLH partner challenge: Best Use of Gemma 4

- Use a Gemma model through the Gemini API
- Name the model in the README and show the integration in code or the demo

Prize: MLH swag bag for the winning team.

## Demo and judging

- Teams stay at their tables, judges come around.
- About 5 minutes per team, then 1-2 questions.
- Show the project, live demo when possible.
- Cover: the problem, the solution, what makes it unique, the technology used.
- Every team member should know how the demo runs before judging starts.
- An unfinished project should still be presented: what was built, what works, what didn't, what was learned, what comes next.

## Judging criteria (weighted equally)

| Criterion | What judges look for |
|---|---|
| Idea | How well it fits the theme and track |
| Implementation | Every feature shown actually works. Complexity of the project and features |
| Design | Is the interface intuitive? Does the design lead users to the features? Is it scalable? |
| Presentation | Why this project, what problem it solves, hardships and how they were overcome, clear feature explanation |
| Track application | How well the track's technologies or problems were used |

Not judged: a fully functional large-scale product, or code complexity. A prototype with some working features and messy code is fine.

## What this means for Gator Radar

- **Only show features that work.** "All features presented are working" is a scoring line, so a small working demo beats a wide broken one.
- **GDG track needs the hackathon Cloud credits**, not a personal Gemini key. Deploy on Cloud Run and use Firestore on the credited project.
- **Gemma 4 challenge is nearly free to add:** route one Gemini API call through a Gemma model and name it in the README.
- **Open-source track needs a public repo with a license.** The repo is private right now.
- **The pitch must say out loud:** who at SFSU benefits, the pilot path, and the responsible-AI risks and fixes.
